## User request and implementation

The user requested a running-status check every 30 minutes and shutdown when
everything finishes. No callable app automation-update tool was exposed in this
session. A local user-systemd timer implements the checks independently of the
chat. It does not create scheduled chat notifications.

`qwen-nvfp4-mtp13-20260926-monitor.timer` uses `OnActiveSec=30min` and
`OnUnitActiveSec=30min`, accuracy1s. Its first scheduled check is
**2026-09-26T01:04:40Z (02:04:40 BST)**. The oneshot service executes:

```bash
uv run --offline --no-project --python 3.12 <suite-archive>/monitor.py <suite-archive>
```

Each check saves suite/systemd/Docker state, completed concurrency summaries,
current trial request counts, and live GPU/SGLang export sizes/timestamps to
`monitor-status.json` and append-only `monitor-checks.jsonl`. All artifacts are
in the same external experiment directory. Saved timer properties are in
`monitor-timer-config.txt`.

The experiment driver already stops each owned server after its round and has
an independent ExecStopPost cleanup hook. The monitor checks for all twenty
expected concurrency summaries (three trials each) and verifies both experiment
containers are stopped. If a terminal or unexpectedly stopped driver leaves
an owned container running, it invokes the saved cleanup mode. Once shutdown
is confirmed, it stops its own timer and appends a final journal entry. Failed
or incomplete trials are labelled as such. Timer shutdown may occur at the
next 30-minute check; benchmark/server shutdown happens in the driver at exit.

## Initial check failure and fix

```text
RuntimeError: Cannot inspect inferpack-qwen38-nvfp4-mtp1-c64-20260926:
error: no such object: inferpack-qwen38-nvfp4-mtp1-c64-20260926
```

MTP=1 is queued and its container does not exist yet. The monitor recognized
only capitalized `No such object`; this Docker client returned lower case.
Normalize the error to lower case and treat the missing queued container as
`created=false`, while preserving other Docker inspection failures as errors.
The original monitor script and failed observation are retained externally.
This was a monitor preflight failure; the benchmark was not interrupted.

## Lesson

Validate an unattended monitor against both running and queued states before
scheduling it. Distinguish an uncreated queued service from Docker access errors,
and preserve checks locally when chat scheduling is unavailable.
