## Memory decision and observed MTP=3 qualification

Pinned engine source charges both `(slots+1)` persistent state and
`(admission+1) * draft_positions` intermediate state. MTP=3 at the old
72/288 configuration would require roughly another 10 GB of float32 state.
Use 64/256 for both new variants to fit MTP=3 without increasing static memory
or changing state precision. MTP=1 may have a larger resulting KV pool; report
actual allocations. This is a matched deployment comparison, not proof that
every byte of the memory layout is identical.

MTP=3 started at **00:13:01Z**. It allocated 256 persistent slots, 36.14 GB SSM,
0.71 GB convolution, 36.56 GB intermediate SSM, and 0.36 GB intermediate
convolution state. Target KV capacity is **83,041 tokens** (1.27 GB K and 1.27 GB V).
API qualification verified effective admission64, three exact chat responses,
the Responses API exact-text result, and a forced 256-token output. All passed.
The longer output ensures speculative gauges update before checking steps3 and
four verification positions. No startup OOM or unexpected restart was observed.

Expected readiness probes returned connection refusal during model loading;
the service became ready within its startup allowance. Known optional torchcodec,
NVML memory-capacity fallback, and FP8 KV fallback-scaling warnings remain in
the saved logs. Text smoke checks passed; broad quality equivalence is untested.

Three preflight trials completed with eight measured requests each, zero client
errors, and no cancellation. Actual exports contain per-trial GPU utilization,
temperature, power/energy and SGLang metrics, with advancing estimated-FLOPs
counters and the expected speculative settings. Verification details are in

## Durable driver, metrics, and shutdown

The suite archive contains `suite.py`, `plan.json`, a snapshot of the shared
benchmarking rules, saved launch commands, and a README. Its service is
`qwen-nvfp4-mtp13-20260926.service`, launched with uv-managed Python3.12.
`status.json` and `events.jsonl` record the currently active step/concurrency.
Individual AIPerf trials retain inputs, client aggregates/requests, GPU samples,
and all SGLang raw JSONL/JSON/CSV exports, with native multi-run confidence reports.

The driver verifies all three trial exports after each concurrency. It saves
throughput, response time, and **SGLang estimated TFLOPS/GPU**, using the first/last
counter scrape strictly inside each measured request window. Edge fractions
are excluded; the interval is recorded. Counter resets are rejected. This is
a model estimate, not measured hardware FLOPs, and speculative-work accounting
must be considered when comparing settings. Unsupported NVML capacity and missing
API prompt-cache token fields are unavailable, not zero; independent SGLang cache
metrics are retained.

After the MTP=3 sweep, the driver stops that server and starts/qualifies MTP=1.
It stops each owned server after its round, including failure/cancellation,
and checks Docker state. A systemd **ExecStopPost** hook independently repeats
cleanup if the main driver exits. Runtime is bounded to eight hours as a failure
backstop, not a duration-based measurement. All raw data and failed attempts
remain external. Final shutdown evidence is in `shutdown-verification.json`
and `fallback-shutdown-verification.json`. Observed qualifications, completions,
and failures append new journal entries with fresh IDs.
