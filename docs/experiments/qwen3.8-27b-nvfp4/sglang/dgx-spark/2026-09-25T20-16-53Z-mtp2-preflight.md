## MTP configuration decision

The user confirmed that **MTP=2 means two drafting steps**:
`--speculative-algorithm EAGLE --speculative-num-steps 2
--speculative-eagle-topk 1 --speculative-num-draft-tokens 3`.
The third position is the additional target verification position, not a third
drafting step. The native single MTP layer is reused across drafting steps.

The cached checkpoint has 15 `mtp.*` tensors across three shards and
`mtp_num_hidden_layers=1`. Its quantization exclusion list contains `mtp*`.
The pinned runtime's `_mtp_quant_config` explicitly leaves this ModelOpt MTP
module unquantized, and its worker supports sharing the target's quantized
language-model head. No separate draft checkpoint or runtime upgrade is needed
for the planned qualification; actual loading remains to be verified.

At 72 requests, the pinned cache-sizing code reserves intermediate state for
`(72 + 1) * 3` positions. Based on the baseline's float32 state size this adds
approximately 31 GB. The baseline's 0.70 static-memory budget and 360 persistent
slots therefore cannot simply be reused. The next attempt will request 72
running requests, 288 persistent slots, `extra_buffer_lazy` (four slots per
request), and a 0.90 static-memory fraction. Float32 Mamba state, FP8 KV cache,
32K context, and 2,048-token prefill chunks remain the same. Lazy buffering was
previously exercised by this repository's FP8 MTP experiments. These memory
settings differ from the NVFP4 baseline and must be disclosed in comparisons.
ReplaySSM will remain disabled.

## Lesson

Distinguish sandbox access failures from hardware failure by checking the same
read-only command with host access. Native MTP requires its own state-memory
budget; the ordinary-decoding admission limit does not establish MTP capacity.
